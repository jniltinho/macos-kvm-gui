# Design

## Decisions

1. **Profile: OCLP 2.5.1's own settings for Kepler** (efi_builder/security.py, misc.py, payloads/Config/config.plist): `csr-active-config` 0x803 (`03080000`), AMFIPass instead of `amfi=0x80`, `ipc_control_port_options=0`, RSRHelper with `-nokcmismatchpanic`, RestrictEvents with `revblock=media`, KDKlessWorkaround with `MinKernel` 22.3.0, the other kexts' `MinKernel` as in OCLP's config (RestrictEvents 12.0.0, AMFIPass and RSRHelper 20.0.0). `SecureBootModel` is already `Disabled`. The app's quirks, Mac model and EFI stay; OCLP's "Build and Install OpenCore" must never be used.
2. **Kexts are downloaded, not embedded.** AMFIPass, RSRHelper and KDKlessWorkaround exist only as binaries inside OCLP's repository, with no separate license of their own; redistributing them in the app's releases would be redistributing binaries on unclear terms. Turning the mode on downloads the four archives from OCLP's repository at the 2.5.1 commit (`f40057a…`), checks each against a pinned SHA-256 and unpacks only `<Name>.kext` (no paths leaving it, no links) into `<Workspace>/.kexts/oclp-2.5.1/`; `PrepareBoot` copies them into the VM's EFI while the mode is on. THIRD_PARTY_NOTICES names the source and OCLP's license.
3. **NVRAM transitions without changing other VMs.** OpenCore's NVRAM Add never replaces a variable that exists. With the mode on, `csr-active-config` and `revblock` are in Delete and Add (so the lowered values apply at once). A marker file in the VM's boot folder records an "on" boot; while it is there, boots with the mode off add the Delete entries again with the default Add values (`csr-active-config` 0, no `revblock`). It is removed only after such a boot ran for a minute (OpenCore applies NVRAM within seconds), never when a config is merely written (`workspace create`, a QEMU that fails), and full bundles carry it with `OVMF_VARS`. A VM that never had the mode gets exactly the earlier configuration, so a SIP value the user set with `csrutil` is kept.
4. **Kepler by explicit IDs**: OCLP 2.5.1's `kepler_ids` (160), vendor `10de`. Eligible like supported AMD cards (IOMMU, host display, slot rules); `GPUReady` allows it natively up to Big Sur, only with the mode from Monterey to Sequoia, never on Tahoe. The vfio reservation adds `softdep nouveau/nvidia pre: vfio-pci`.
5. **Consent**: the GUI explains what is weakened before turning the mode on, and asks to confirm the root patch was reverted before turning it off; the CLI needs `--root-patch-reverted` for that.
