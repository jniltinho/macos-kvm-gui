# Design

## Context

`BuildArgs` (`internal/core/vm.go`) builds one QEMU command for every VM: q35, `qemu-xhci` with USB keyboard and tablet, `isa-applesmc`, ICH9 HDA, OpenCore on a vvfat virtio-blk disk, `vmware-svga` always (kept beside a passed-through GPU for the console), and in-app display over VNC on a Unix socket plus two QMP sockets. QEMU is run as `qemu-system-x86_64` from `PATH`. Running VMs are found through `/proc/<pid>/comm` starting with `qemu-system`. VM settings live in SQLite (`vms` table, schema 3); user settings in `settings.yaml` (change `add-extra-kexts`).

Upstream (steelbrain/reims-vgpu, commit `c099dd5a4d`): the library is linked statically into a QEMU fork that adds `apple-gfx-pci` (PCI `106b:eeee`, with an option ROM `ReimsVgpu.rom` QEMU finds in its data directory). `scripts/install-ctl.sh` builds the library (Rust 1.98.1, SDL3 from source), QEMU (`--target-list=x86_64-softmmu --enable-kvm --enable-gtk --enable-slirp --enable-pvg`, prefix `/reims-ctl-qemu`, relocatable) and installs it into `$XDG_DATA_HOME/reims-ctl/qemu/<date>-<commit>` with a `current` link, plus `reims-ctl` and `reims-util` via `cargo install`. reims-ctl's measured x86-64 command (`crates/reims-ctl/src/qemu.rs`): memfd RAM (`-machine q35,memory-backend=ram` + `memory-backend-memfd,share=on`), `ICH9-LPC.disable_s3=1`, `-vga none`, `apple-gfx-pci,bus=pcie.0,addr=0x4,displays=1,resolution=1920x1080`, `qemu-xhci,addr=0x5,conditional-intr-mapping=on` with keyboard/tablet, `usb-audio` on xHCI (macOS 26 has no HDA driver) plus ICH9 HDA for OpenCore's chime, `-display none` (the library opens its own SDL3/Vulkan window). Headless console reads are slow (about 1.7 s per 1080p frame on an RTX 5080 laptop), so VNC is not a usable main screen.

## Goals / Non-Goals

**Goals:**
- Run any VM on Reims vGPU with one setting, keeping disks, OpenCore, NVRAM and identity as they are.
- A reproducible build for Ubuntu 24.04 and 26.04 hosts that touches nothing on the host but the install folders.

**Non-Goals:**
- Embedding Reims vGPU in the app binary, or updating upstream automatically.
- reims-ctl's VM format, reims-util's OpenCore images, multiple displays, HiDPI or `resolution=host`, ReimsVgpu.kext (needed above 2048 px; it can be listed in `kexts` of `settings.yaml`).
- Other distributions; arm64 hosts.

## Decisions

- **Graphics enum per VM.** `Config.Graphics` (`"" | "vmware-svga" | "reims-vgpu"`, empty = `vmware-svga`), SQLite schema 4 adds a `graphics TEXT NOT NULL DEFAULT ''` column (same safe-to-repeat migration as `root_patch`), JSON export/import carries it. `Validate` refuses `reims-vgpu` together with `GPU`. Alternative: a global setting, rejected because a VM installed on Reims needs `METAL_ERROR_MODE` and users will mix VMs.
- **Which QEMU.** `ReimsQEMU()` returns, in order: `reims_qemu` from `settings.yaml` (new key, `MKG_REIMS_QEMU` precedence), `<Workspace>/.reims/qemu/current/bin/qemu-system-x86_64` (the app's own builds, beside `.kexts` and `.installers`), then an upstream install at `$XDG_DATA_HOME/reims-ctl/qemu/current/bin/qemu-system-x86_64`. `vm.Start` runs it instead of `qemu-system-x86_64` for Reims VMs, and probes `-device help` once per binary (cached by path and mtime) for `apple-gfx-pci`. `/proc/<pid>/comm` is still `qemu-system-x86`, so running-VM detection keeps working.
- **Arguments.** `BuildArgs` branches only where the measured command differs: memfd-backed `-machine`/`-object`, `-global ICH9-LPC.disable_s3=1`, `-vga none`, `apple-gfx-pci,id=gfx,displays=1,resolution=1920x1080` instead of `vmware-svga`, with **no fixed `addr`** (upstream's `0x4` collides with the app's `ich9-ahci`, which QEMU places there first; the app's OpenCore boots by scanning, not by device paths), `-audiodev <pipewire|pa|none>,id=snd0` bound to both `hda-duplex,audiodev=snd0` and `usb-audio,audiodev=snd0,bus=xhci.0` (an explicit audiodev leaves an unbound codec without a default driver), and `conditional-intr-mapping=on` on xHCI. Everything else (CPU profile, SMC, OpenCore vvfat disk, disks, NICs, QMP) is unchanged, so an existing VM boots the same OpenCore. The extra `usb-ehci` stays (nothing is on it). A test realizes the command paused (`-S`) with the built QEMU when it is installed (skipped otherwise), besides golden argument tests.
- **Display.** Reims VMs always run `-display none` (window mode) with `REIMS_VGPU_WINDOW` removed from QEMU's environment; the VNC socket is still added (`-vnc` without `-display` would also be window mode, so both coexist), giving the Preview, `screen_capture` and key/pointer input over QMP as today. The GUI's VNC consumer is split in two: a preview-only connection that feeds the Preview (and reconnects for VMs started by the CLI or MCP, through `watchOutside`), and the interactive Screen attachment, which Reims VMs never get; their Screen tab shows "The screen is in the Reims vGPU window". Alternative: VNC as the screen, rejected (frame reads take seconds).
- **Host checks.** New `reims.go` with pure functions over `Host`'s roots for testing: QEMU found + `apple-gfx-pci`; Vulkan ICD manifest present; `vm.max_map_count >= RAMMiB*64 + 65536` (upstream: 64 mappings per MiB plus a reserve of 16,384 and the process's own); any AMD GPU (`/sys/class/drm/card*/device/vendor == 0x1002`) without read-write `/dev/udmabuf` ⇒ a warning only, since QEMU may render on another GPU and the app cannot know which Vulkan device the library picks; `explainExit` turns a udmabuf failure into the group hint. Run in `vm.Start` for Reims VMs and listed in the Host tab (warnings when no Reims VM exists).
- **Prebuilt packages.** A separate workflow, `.github/workflows/reims-release.yml`, runs on `reims-<short commit>` tags (independent of app releases, since upstream moves at its own pace and each build takes about 10 minutes per release): a matrix over 24.04 and 26.04 runs the same Dockerfile the app embeds, strips the binaries, packs `qemu/` as `tar.zst` (measured: 323 MB unpacked, 29 MB packed for 24.04), writes `.sha256` files, and a second job makes the source archive (`git archive` of upstream with `vendor/qemu`, plus `cargo vendor` output) and `THIRD_PARTY_NOTICES` for QEMU (GPL-2.0), the library (GPL-2.0-or-later or LGPL-3.0-or-later), SDL3 (zlib) and the Rust crates. Publishing the source in the same release meets GPL-2.0's distribution terms. The app embeds `internal/core/reims/manifest.json` (tag, commit, per-release file and SHA-256), updated by a commit after a reims release; `InstallReims(ctx, log)` downloads with `httpsGetMax`, verifies, unpacks with the same path and link checks as kext archives, and promotes like a build. Alternative: attach the packages to every app release, rejected (doubles release time, re-uploads identical binaries).
- **Docker build, embedded recipe (fallback).** The app embeds `internal/core/reims/Dockerfile` (`ubuntu:<release>`, upstream's apt package list, rustup with the pinned toolchain, upstream cloned at a pinned commit, `cargo fetch`) and drives it from Go (`BuildReims(ctx, release, log)`), used by the Host tab button and `reims build`. Steps: check the release (default: `/etc/os-release` when 24.04 or 26.04) and `docker info`; take a host-wide flock (`$XDG_RUNTIME_DIR/macos-kvm-gui-reims-build.lock`, held through promotion); `docker build`; `docker run` upstream's `install-ctl.sh --yes` as root with `XDG_DATA_HOME`, `XDG_CACHE_HOME` and `CARGO_INSTALL_ROOT` on mounted folders under `<Workspace>/.reims/build-<release>` (also the build cache), `strip` on the binaries, and `chown` to the user. The new `qemu/<build>` is then staged into `<Workspace>/.reims/qemu/`; on the host, `ldd` must resolve every library (missing ones are mapped to Ubuntu packages in the message) and `-device help` must list `apple-gfx-pci`; only then is `current` relinked atomically (a temporary link renamed over it). A build for a release other than the host's stays staged. Old builds are pruned only when no running QEMU's `/proc/<pid>/exe` points into them. `reims-ctl` and `reims-util` are not installed (the app does not need them). Embedding binaries instead was rejected: about 500 MB per release unstripped, linked against each release's libraries, and a GPL redistribution the app avoids by building from source on the user's machine.
- **Guest guidance.** Selecting `reims-vgpu` shows the `METAL_ERROR_MODE` commands (desktop and Recovery forms) and the 2048-px note; `docs/reims-vgpu.md` repeats them with the build and host steps.

## Risks / Trade-offs

- [Upstream is beta and changes fast] → pinned commit in the build script; the app only depends on `apple-gfx-pci`'s properties used above.
- [Guests other than macOS 26 are unmeasured upstream] → offered with a note, per the user's choice; the VM keeps its disk, so switching back to `vmware-svga` recovers it.
- [A new install's desktop never appears without `METAL_ERROR_MODE`] → shown when the option is chosen, documented with the Recovery commands.
- [Displays above 2048 px crash WindowServer without ReimsVgpu.kext] → resolution fixed at 1920x1080.
- [GPL QEMU binaries on Releases] → the corresponding source archive and license notices go into the same release; the app downloads only what its manifest pins.
- [A package's libraries differ from the host's (point releases)] → activation checks `ldd` and `apple-gfx-pci` on the host first; the Docker build remains.
- [The Docker build downloads a lot (Rust crates, QEMU source, SDL3) and takes about 10–20 minutes] → done once per release, cached, with progress in the log; it measured about 10 minutes on the reference host.

## Migration Plan

Schema 4 adds a defaulted column; existing VMs stay on `vmware-svga`. Rollback: set Graphics back; older app versions ignore the column.

## Open Questions

- Whether `usb-audio` and `conditional-intr-mapping` also suit macOS before 26 (unmeasured upstream); they are only used for Reims VMs.
